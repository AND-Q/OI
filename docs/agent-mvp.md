# OI Agent 最小版本设计

> 日期：2026-10-23 ｜ 状态：设计草案，尚未实施
>
> 本文是 [`agent-plan.md`](agent-plan.md) 的第一步，范围比完整方案小得多：只回答「最小的 agent 做成什么样」，不涉及具体实现。
>
> 2026-10-23 修订：去掉默认关闭的总开关。改为由模型判断是否调用工具，由程序自动检测模型是否支持，在第一次用到时询问你是否允许。

## 1. 目的

做一个能真正调用工具、分几步完成任务的最小 agent，用它验证三件事：

1. 选定的模型能不能稳定地调用工具；
2. 启动器面板能不能承载多步任务；
3. 工具的划分和返回内容是否合理。

确认卡片、记忆、日志、多轮对话等能力，等这三件事验证完，再按完整方案逐步加入。

## 2. 范围

### 2.1 做

- Quick AI 默认带上工具。一次提问就是一个任务：模型自己判断要不要调用工具，可以分几步完成，最后给出回答；不需要工具的提问照常直接回答。
- 提供 5 个工具：找 App、启动 App、找文件、打开文件、在访达中显示。
- 自动判断模型是否支持工具调用：不支持时自动退回纯问答，Quick AI 不会因此失效（第 7.3 节）。
- 第一次真正要调用工具时询问一次是否允许，并记住你的选择；接口在本机时不询问（第 9.2 节）。设置中可以随时修改，也可以关闭工具调用（第 10 节）。
- 回答区逐步显示：每一步调用了什么、结果如何。
- 面板因为失去焦点而收起时，任务继续运行；再次呼出时显示进度或结果。

### 2.2 不做

| 不做 | 原因 |
|---|---|
| 多轮追问 | 先验证单个任务；这是 MVP 之后第一个要加的能力 |
| 会话日志、历史记录 | 任务只保存在内存中，退出即消失 |
| 确认卡片与风险策略 | 本版只提供不需要确认的工具 |
| 移动、删除、写入文件，读取剪贴板，读取文件内容，打开网址 | 都需要确认机制，见完整方案的风险分级 |
| 日历、提醒事项、快捷指令、AppleScript、shell | 需要新的系统授权或沙盒 |
| 记忆、技能、MCP、定时任务、后台通知、状态栏指示 | 不属于最小闭环 |
| 端侧模型、模型路由、独立的 agent 模型配置 | 沿用 Quick AI 的配置即可 |

## 3. 成功标准

- 工具调用被设为关闭、模型不支持工具调用、或你没有允许时，Quick AI 都退回现在的纯问答；划词翻译的行为不变；现有测试全部通过。
- 使用支持工具调用的模型并允许后，第 11.2 节列出的任务都能一句话完成。
- 不需要工具的提问不调用工具，回答方式与现在相同。
- 每一步都显示在回答区。
- agent 打开其他 App 导致面板收起时，任务不会中断。
- 按 `Esc` 仍然会中断任务并关闭面板。
- 工具出错时，模型能看到错误并调整做法。
- 达到步数上限或打开次数上限时，任务停下并说明原因。
- 不会打开 App 包、脚本、安装包这类可执行内容。

## 4. 交互

### 4.1 流程

1. 按 `Tab` 进入 ✨ 模式，输入任务，按 `Enter`。
2. 如果模型第一次要调用工具，而你还没有做过选择，回答区会先出现询问（第 9.2 节）：按 `Enter` 允许，按 `Esc` 不允许。
3. 回答区依次出现：模型的说明文字、每一步的步骤行、最终回答。
4. 页脚显示「运行中 · 第 n 步」，或者完成、失败的状态。
5. 完成后按 `Enter` 复制最终回答并关闭面板，与现在相同。

### 4.2 按键与面板

| 操作 | 行为 | 与现在相比 |
|---|---|---|
| `Enter` | 输入态：发送；运行中：不响应；完成：复制回答并关闭；失败：重试 | 不变 |
| `Esc` | 中断任务并关闭面板 | 不变 |
| 询问是否允许调用工具时 | `Enter`：允许并继续；`Esc`：不允许，本次直接回答，之后不再带工具 | 新增 |
| 点击别处，或 agent 打开了其他 App | 面板收起，任务继续运行 | **改变** |
| 再次呼出面板 | 任务还在运行，或在 10 分钟内完成：显示这个任务；否则进入新的输入态 | **改变** |
| 修改问题 | 丢弃当前任务，回到输入态 | 不变 |
| `⌘C`、`↑` / `↓`、`Tab` | 复制、滚动、返回检索 | 不变 |

面板行为只改两处，都是为了不让任务被自己打断：agent 一旦打开别的 App，OI 就会失去焦点。另外新增一次性的询问，用来确认是否允许调用工具；询问显示期间，`Enter` 和 `Esc` 只用于回答询问。

### 4.3 步骤行

- 每一步占一行：图标、工具的中文名、关键参数、结果摘要、状态（进行中、完成、失败）。
- 例如：「🔍 搜索文件：发票 · 找到 6 个 ✓」「📂 在访达中显示：发票-1015.pdf ✓」。
- 本版不提供展开查看详情。
- 回答区沿用现在的固定高度，内容超出时滚动。

## 5. 方案决策

采用：

- 在现有的 Quick AI 内实现：同一个入口，同一套配置（接口地址、模型、Key、思考强度）；
- 是否调用工具由模型判断，模型是否支持工具由程序自动检测，是否允许发送 App 名称、文件名和路径由你决定；
- 自建最小循环：请求模型 → 执行工具 → 回填结果，直到模型给出回答，或碰到上限；
- 使用 OpenAI 兼容接口的标准工具调用（`tools` / `tool_calls`）；
- 工具只包装现有用例，不新增任何系统权限；
- 任务状态只保存在内存中。

本版明确不采用：

- 新的入口或独立窗口；
- 默认关闭的总开关；
- 任何需要确认的工具；
- agent 框架、Foundation Models；
- 多轮对话、日志、记忆。

### 5.1 选择理由

- **三个判断分开处理**：
  - **这次要不要用工具，交给模型**：请求带上工具定义后，由模型自己决定。问「介绍一下 Xcode」时直接回答，说「打开 Xcode」时才调用工具。
  - **模型支不支持工具，交给程序**：接口明确报错时，自动退回纯问答并记住，用户几乎感觉不到。当初考虑默认关闭开关，就是怕不支持工具的模型让 Quick AI 失效；自动退回同样能避免这一点。
  - **要不要把 App 名称、文件名和路径发给接口，交给你**：这是隐私决定，模型不能替你同意，所以在第一次用到时问一次。接口在本机时，数据不会离开这台 Mac，不必询问。
- **仍然保留关闭选项**：有的模型声称支持工具，但用得很差，比如乱调用、参数总是填错。这种情况程序判断不出来，所以要让你能手动关闭。
- **只选不需要确认的工具**：这样本版不用做确认界面和风险策略，也能把循环本身验证清楚。这几个动作在启动器里本来就是一键可做的。
- **单轮、不落盘**：先把「模型 + 工具 + 面板」这条主线跑通。多轮和日志在完整方案里已经设计好，之后加上去只是追加消息、持久化任务，不需要返工。
- **`Esc` 仍然中断任务**：尽量少改按键的含义。只修正「面板失焦收起时任务被中断」这一处，因为不修，agent 每打开一个 App 都会把自己打断。

## 6. 架构

```text
Quick AI（✨ 模式）
  └─ LauncherViewModel：任务状态（问题、步骤、回答、运行状态）
       └─ RunAgentTask（用例）：循环、上限、错误回填
            ├─ 模型端口：消息 + 工具定义 → 文字增量 / 工具调用
            │    └─ OpenAICompatibleQuickAIClient（增加工具调用）
            └─ 工具（5 个）
                 ├─ app_search    → 共享的应用快照
                 ├─ app_launch    → LaunchApplication
                 ├─ file_search   → SearchFiles
                 ├─ file_open     → OpenFile
                 └─ file_reveal   → OpenFile
```

| 层 | 新增或修改 |
|---|---|
| Domain | 工具调用（id、名称、参数）等与模型服务无关的数据类型 |
| Application | 模型端口增加「多条消息 + 工具定义」的流式请求；工具协议；`RunAgentTask` 用例（包括不支持工具时的自动退回）；5 个工具；共享的应用快照 |
| Infrastructure | OpenAI 兼容客户端：请求时带工具定义，解析流式的工具调用，回填工具结果；设置存储增加「工具调用」选项和「不支持工具」的记录 |
| Features | Quick AI 的会话状态增加步骤列表和「等待允许」状态；回答区显示步骤行和首次询问 |
| UI | 面板失焦收起时不再中断任务；再次呼出时恢复显示 |
| App | 组装工具；读取「工具调用」设置 |

约束：

- 划词翻译继续使用现有的单轮接口，不受影响。
- 应用索引目前是 `LauncherViewModel` 的私有属性。需要改成共享的只读快照：启动器刷新时写入，`app_search` 读取。
- 依赖方向保持不变：工具放在 Application 层，只依赖用例和端口。

## 7. Agent 循环

### 7.1 流程

1. 组装消息：系统提示、当前时间、用户的任务。
2. 带上 5 个工具的定义请求模型，并流式接收。如果「工具调用」设为关闭，或已经知道该模型不支持工具，就不带工具定义，等同于现在的纯问答。
3. 如果模型只回了文字，任务完成。
4. 如果模型要调用工具，就逐个执行，把结果作为工具消息加回对话，然后回到第 2 步。
   - 第一次调用之前，如果还没有你的允许，先询问（第 9.2 节）；
   - 你不允许时，把「未获允许」作为工具结果交给模型，让它直接回答。

### 7.2 上限

- 每个任务最多 10 次模型请求。
- 每个任务最多 5 次打开类操作，包括 `app_launch`、`file_open`、`file_reveal`。超出时，工具返回错误「本次任务已达到打开次数上限」。
- 同一工具以同样的参数连续调用 3 次时，停止任务。
- 两次收到数据之间的超时，沿用现在的 3 分钟。

### 7.3 出错

- **工具执行失败**：错误信息作为工具结果交给模型，任务不中断。
- **参数不对**：返回错误说明和正确格式，让模型重试。
- **接口出错**：任务失败，显示原因，按 `Enter` 重试，与现在相同。
- **模型不支持工具调用**：
  - 接口明确报错不支持工具时（例如 Ollama 返回 `does not support tools`），自动去掉工具定义重发一次，这次提问照常得到回答；
  - 同时记住这个「接口地址 + 模型」不支持工具，之后直接走纯问答；
  - 更换接口地址或模型后重新判断；
  - 只有错误信息明确提到工具时才这样判定，其他错误照常显示，不做记录。
- **接口忽略工具定义**：有的服务不报错，只是从不调用工具。表现与纯问答相同，不需要处理。

### 7.4 系统提示要点

- 你是 OI 启动器里的助手，可以用工具找 App、找文件，打开它们或在访达中显示。
- 先查再做；打开或启动之前，确认目标就是用户要的那个。
- 找不到时如实说明，并列出相近的结果。
- 信息不够时直接说明还需要什么。本版不支持追问，用户会重新输入完整的任务。
- 回答简洁，使用与提问相同的语言。

## 8. 工具

| 工具 | 作用 | 参数 | 返回 | 限制 |
|---|---|---|---|---|
| `app_search` | 按名称、拼音、首字母找 App | 关键词；数量，默认 5 | 名称、bundle id、id | 只读 |
| `app_launch` | 启动 App，或切到前台 | `app_search` 返回的 id | 「已启动」或「已在运行，已切到前台」 | 只能启动 OI 应用列表中的 App；计入打开上限 |
| `file_search` | 按名称搜索文件和文件夹 | 关键词；数量，默认 10 | 名称、路径（`~` 缩写）、文件还是文件夹、最近活动时间 | 只读；只返回名称、路径这类元数据，不读内容；范围与现有文件搜索相同；设置中关闭了文件搜索时返回错误 |
| `file_open` | 用默认 App 打开 | 路径 | 「已打开」 | 只接受本次任务中 `file_search` 返回过的路径；拒绝可执行内容；计入打开上限 |
| `file_reveal` | 在访达中显示 | 路径 | 「已在访达中显示」 | 只接受本次任务中 `file_search` 返回过的路径；计入打开上限 |

设计规则：

- **返回要简洁**：每个结果一行，最多 10 条；结果有更多时，注明总数，并提示可以换更具体的关键词。
- **错误要能指导下一步**：例如「没有找到名为『微信』的 App；相近的有 WeChat」。
- **只接受搜索过的路径**：`file_open` 和 `file_reveal` 只接受本次任务中搜索返回过的路径。这样模型不能编造路径，也打不开搜索范围以外的文件。
- **可执行内容按文件类型判断**：包括 App 包、脚本、安装包、磁盘映像、自动化流程、终端配置、网址快捷方式等。这些都不允许打开。

## 9. 安全与隐私

### 9.1 为什么本版不需要确认

- 所有工具要么只读取名称和路径，要么执行你在启动器里一键就能做的事：启动 App、打开文档、在访达中显示。
- 不读取文件内容、剪贴板或网页，几乎接触不到不可信内容。
- 没有任何能把数据发出去的工具：不打开网址，不联网。
- 另外还有三道限制：打开次数上限、只接受搜索过的路径、拒绝可执行内容。

在致命三角（私有数据、不可信内容、对外通信）中，本版缺少后两条，所以可以不做确认。以后加入读取内容或对外通信的工具时，必须先有完整方案中的确认机制和会话污染标记。

### 9.2 隐私

- 允许调用工具后，App 名称、文件名和路径会作为工具结果发送给模型服务。
- **首次询问**：模型第一次要调用工具、而你还没有做过选择时，在回答区询问：
  > 允许 Quick AI 搜索 App 和文件吗？App 名称、文件名和路径会发送给 <接口主机>。
  - 按 `Enter` 允许：继续执行，之后不再询问；
  - 按 `Esc` 不允许：把「未获允许」作为工具结果交给模型，让它直接回答；之后的提问不再带工具，设置随之变为「关闭」，可以在设置中改回。
- **「允许」与接口主机绑定**：更换接口主机后，恢复为「首次使用时询问」。因为同意的是把数据发给某一家服务，换了服务就要重新问。
- **本机接口不询问**：接口地址是本机（`localhost`、`127.0.0.1`、`::1`）时直接允许，因为数据不会离开这台 Mac。局域网里的其他设备不算本机，仍然要询问。
- 设置项的说明文字、功能清单和使用指南中的隐私说明同步更新。

## 10. 配置

- Quick AI 设置新增「工具调用」一项，有三个选项：
  - **首次使用时询问**（默认）：行为见第 9.2 节；
  - **允许**：不再询问；更换接口主机后恢复为「首次使用时询问」；
  - **关闭**：始终是纯问答，与现在的 Quick AI 完全一致；更换接口主机也保持关闭。
- 首次询问中的选择会写回这一项。
- 说明文字：
  > 允许后，Quick AI 可以搜索 App 和文件，并打开它们或在访达中显示。App 名称、文件名和路径会发送给接口。模型不支持工具调用时，自动改为直接回答。
- 「某个模型不支持工具」的记录不在设置中显示；更换接口地址或模型后自动重新判断。
- 接口地址、模型、API Key、思考强度都沿用 Quick AI 现有的设置。

## 11. 测试与验收

### 11.1 单元测试

用桩代替真实模型和系统能力，沿用项目现有的测试写法。

- **客户端**：
  - 请求中带上了工具定义；
  - 分片到达和一次给全的工具调用都能拼接完整；
  - 工具结果按正确格式回填。
- **循环**：
  - 用脚本化的模型桩，先返回工具调用，再返回回答；
  - 各项上限生效；
  - 工具错误能回填给模型；
  - 重复调用时停止；
  - 接口明确报不支持工具时，去掉工具重发并记住；换了模型后重新判断；其他错误不会被误判为不支持。
- **工具**：
  - 参数校验；
  - 拒绝可执行内容；
  - 只接受搜索过的路径；
  - 打开次数上限。
- **面板**：
  - 失焦收起时任务不中断；
  - `Esc` 中断任务；
  - 再次呼出时恢复显示。
- **设置与询问**：
  - 设为「关闭」时，请求不带工具；
  - 首次询问中允许、不允许两条路径都正确，选择会写回设置；
  - 本机接口不询问；
  - 「允许」在更换接口主机后恢复为「首次使用时询问」。

### 11.2 手工验收

在 Xcode 中运行，使用一个支持工具调用的模型：

1. 「打开微信」：先调用 `app_search`，再调用 `app_launch`。
2. 「打开 wyy」：通过拼音首字母找到网易云音乐并启动。
3. 「找到 OI 项目里的 README，在访达中显示」：先调用 `file_search`，再调用 `file_reveal`。
4. 「打开最近下载的发票」：先调用 `file_search`，再调用 `file_open`。
5. 「打开所有 pdf」：碰到打开次数上限后停下并说明。
6. 「打开 install.command」：拒绝，并说明原因。
7. 「今天天气怎么样」：不调用工具，直接说明无法获取。
8. 发送任务后立刻点别处，再呼出：任务仍在继续，或已经完成。
9. 运行中按 `Esc`：任务中断，面板关闭。
10. 在设置中把「工具调用」改为「关闭」后提问：与现在的 Quick AI 完全一致。
11. 把「工具调用」改回「首次使用时询问」，第一次触发工具时出现询问，按 `Enter` 后继续执行。再改回「首次使用时询问」试一次，这次按 `Esc`：本次直接回答，设置变为「关闭」。
12. 改用本机 Ollama 上一个不支持工具调用的模型：不出现询问，照常得到回答。

至少用两家支持工具调用的服务实测（例如 DeepSeek 和通义千问），记录各自的成功情况和问题。

## 13. 风险

| 风险 | 处理 |
|---|---|
| 模型的工具调用质量参差不齐 | 至少实测两家服务；不支持时自动退回纯问答；用得很差的模型可以在设置中关闭 |
| 把别的错误误判为「不支持工具」 | 只有错误信息明确提到工具时才判定；其他错误照常显示，不做记录 |
| 各家流式工具调用的格式不同 | 同时兼容分片到达和一次给全两种情况，用单元测试覆盖 |
| 思考模式与工具调用组合时，部分服务要求回传思考内容 | 实测；需要时在客户端中适配 |
| 面板固定高度放不下太多步骤 | 步骤行只占一行；回答区可以滚动 |
| 打开的 App 抢走焦点 | 失焦收起时不中断任务，这是本版的核心修改 |
