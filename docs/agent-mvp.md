# OI Agent 最小版本设计

> 日期：2026-10-23 ｜ 状态：设计草案，尚未实施
>
> 本文是 [`agent-plan.md`](agent-plan.md) 的第一步，只回答「最小的 agent 做成什么样」，不涉及具体实现。
>
> 修订记录：
> - 第一版：5 个与手动操作重复的工具，加一个默认关闭的总开关。
> - 第二版：去掉总开关，改为自动检测，并在首次使用时询问。
> - 本版（第三版）：参照 Raycast AI 扩展的成熟做法重写——用 `@` 选择扩展，工具自带确认，只做 `@文件` 一个扩展。

## 1. 目的

做一个最小但有用的 agent：在 Quick AI 里用 `@文件` 按描述找文件、批量整理文件。它要验证三件事：

1. Raycast 的扩展模型（工具 + 确认 + 用 `@` 选择）能否在 OI 里跑通；
2. 选定的模型能否稳定地调用工具；
3. 「按描述找文件」和「批量整理」这类手动做不到的事，你会不会真的常用。

## 2. 参照对象：Raycast 的 AI 扩展

| Raycast 的做法 | OI 最小版本 |
|---|---|
| 在根搜索按 Tab 进入 Quick AI；Quick AI 是一段持续的对话：打字即追问，⌘N 开新对话，闲置一段时间后自动开新对话 | 采用，沿用现有的 Tab ✨ 模式 |
| AI 扩展由一组工具和一段领域说明组成；领域说明描述对象和规则，不写角色设定 | 采用，本版只做 `@文件` |
| 工具由带说明的输入和执行函数组成，另有一个可选的确认函数：它在执行前用同一份输入调用，返回空就跳过确认，否则返回卡片内容（说明、明细、是否用破坏性样式） | 采用 |
| 在输入框中用 `@` 选择扩展，可以同时选多个；不选就是普通问答；2.x 另有自动发现扩展 | 采用 `@`；自动发现以后再做 |
| 权限分 Ask / Auto / Always Allow 三档；确认卡片上 ↵ 允许、⌘↵ 总是允许、Esc 拒绝；「总是允许」过的工具记在列表里，可以查看和清空 | 只做「工具自带的确认 + 总是允许」，不做三档 |
| 评测：带 `@` 的输入 + 各工具的模拟返回 + 期望；评测同时作为示例提示词展示给用户 | 采用同样的结构 |
| 用 `@` 附带上下文（选中文字、当前窗口、截图）、Agents 预设、AI Chat 窗口、MCP、Skills、定时任务 | 以后再做（第 14 节） |

## 3. 范围

### 3.1 做

- Quick AI 支持追问：一段对话内可以连续提问；⌘N 开新对话；10 分钟没有操作就自动开新对话。
- 在 Quick AI 的输入框里输入 `@` 选择扩展。本版只有 `@文件`。
- 选择 `@文件` 后，这段对话的请求都附带文件工具，由模型决定调用哪些、调用几次。
- 提供 6 个文件工具（第 7.3 节），其中会改动文件的需要先确认。
- 确认卡片，以及「总是允许」。
- 回答区逐步显示每一次工具调用。
- 面板失焦收起时，任务继续运行；再次呼出时恢复显示。

### 3.2 不做

| 不做 | 原因 |
|---|---|
| 其他扩展：`@应用`、`@剪贴板`、`@提醒事项`、`@日历` | 先把一个扩展做扎实 |
| 用 `@` 附带上下文：选中文字、当前窗口、截图 | 需要在呼出面板之前采集，放到下一步 |
| 移到废纸篓、覆盖已有文件、Auto 档 | 需要更细的风险判断 |
| 自动发现扩展（不用 `@` 也能调用工具） | 先用显式的 `@` |
| AI Chat 窗口、历史记录、Agents 预设 | 对话只保存在内存中 |
| MCP、Skills、定时任务、记忆 | 不属于最小闭环 |
| 单独的模型配置 | 沿用 Quick AI 的接口设置 |

## 4. 成功标准

- 不使用 `@` 时，Quick AI 的问答与现在一致（新增的追问除外）；划词翻译不受影响；现有测试全部通过。
- 使用 `@文件` 时，第 11.2 节列出的任务都能完成。
- 会改动文件的操作，都先弹出确认卡片，逐项列出改动；你拒绝后不会执行。
- 「总是允许」生效，并且可以在设置中查看和清空。
- 任务不会因为面板失焦而中断；在确认卡片上按 `Esc` 是拒绝，其他时候按 `Esc` 是中断并关闭面板。
- 不覆盖已有文件，不打开可执行内容。

## 5. 交互

### 5.1 对话

- 按 `Tab` 进入 ✨ 模式（Quick AI），输入问题，按 `↵`。
- 回答完成后：
  - 输入框有文字时按 `↵`：追问；
  - 输入框为空时按 `↵`：复制最后一条回答并关闭面板，沿用现在的习惯。
- ⌘N 开新对话；10 分钟没有操作，下次呼出时自动开新对话。
- 修改输入框里的文字只是在写下一条消息，不再丢弃已有回答。这一点和现在不同。

### 5.2 用 @ 选择扩展

- 在输入框里输入 `@`，弹出扩展列表（本版只有「文件」）。按 `↵` 或点击选中后，输入框中显示为一个标签。
- 选中后，这段对话之后的请求都附带该扩展的工具；⌘N 开新对话后，需要重新 `@`。
- 列表中每个扩展都有一行说明和 2–3 条示例。示例取自评测，参照 Raycast 的做法。
- 不选扩展时，请求不附带任何工具。
- `@文件` 的说明中写明：文件名和路径会发送给接口。

### 5.3 步骤与确认

- 每次工具调用在回答区占一行：图标、工具名、关键参数、结果摘要、状态。
- 需要确认时，回答区底部显示一张确认卡片：
  - 标题：工具的确认函数给出的说明，例如「移动 6 个文件」；
  - 明细：逐项列出「原路径 → 新路径」，超出卡片高度时可以滚动；
  - 按键：`↵` 允许，`⌘↵` 总是允许（以后这个工具不再询问），`Esc` 拒绝。
- 同时有多个调用等待确认时，一次只显示一张卡片，依次确认。
- 拒绝后，把「用户拒绝了这个操作」作为工具结果交给模型，由模型说明情况或换个做法。

### 5.4 按键与面板

| 操作 | 行为 | 与现在相比 |
|---|---|---|
| `↵` | 输入框有文字：发送或追问；运行中：不响应；输入框为空且已有回答：复制最后一条回答并关闭；失败：重试 | 增加追问 |
| `⌘N` | 开新对话 | 新增 |
| `@` | 弹出扩展列表 | 新增 |
| 确认卡片上的 `↵` / `⌘↵` / `Esc` | 允许 / 总是允许 / 拒绝 | 新增 |
| `Esc`（没有确认卡片时） | 中断任务并关闭面板 | 不变 |
| 点击别处，或工具打开了其他 App | 面板收起，任务继续运行 | 改变 |
| 再次呼出面板 | 10 分钟内的对话恢复显示，否则开新对话 | 改变 |
| `⌘C`、`↑` / `↓`、`Tab` | 复制、滚动、返回检索 | 不变 |

面板失焦时不中断任务，是因为「打开」和「在访达中显示」会切走焦点。如果不改，任务会被自己打断。

## 6. 方案决策

采用：

- 参照 Raycast 的扩展模型：扩展由工具和领域说明组成；工具由带说明的输入、执行函数和可选的确认函数组成；
- 用 `@` 显式选择扩展；
- 确认只做「工具自带的确认 + 总是允许」；
- 自建最小循环，使用 OpenAI 兼容接口的工具调用；
- 对话只保存在内存中，不写入磁盘。

本版明确不采用：

- 默认附带工具，或自动发现扩展；
- 总开关、自动检测模型是否支持工具、首次使用时询问；
- Auto 档，即按风险自动判断是否需要确认；
- agent 框架、Foundation Models。

### 6.1 选择理由

- **用 `@` 让三件事都由你明确决定**：这次要不要用工具、用哪一组工具、把哪些数据发出去。所以前两版设计中的总开关、自动检测和首次询问都不再需要。
- **确认放在工具里**：只有工具最清楚这次调用会改动什么，例如要移动哪些文件、会不会覆盖，所以由它生成卡片内容最准确；是否放行由 OI 统一判断。以后加新工具，只要写好它自己的确认函数即可。
- **只做 `@文件`**：按描述找文件、批量整理都是手动做不到的事，而且全部基于现有的文件搜索和打开能力，不需要新的系统权限。
- **支持追问**：模型在动手之前常常需要和你确认细节，比如「是这 6 个吗？」。没有追问，就只能重新输入整个任务。Raycast 的 Quick AI 也是一段持续的对话。
- **不覆盖、不删除**：本版的所有改动都可以手动恢复，出错的代价低。

## 7. 扩展与工具

### 7.1 扩展的组成

每个扩展包括：

- **名称与图标**：显示在 `@` 列表中；
- **说明**：一行文字，告诉你它能做什么、会发送哪些数据；
- **领域说明**：写给模型看，描述对象和规则，不写角色设定。例如：路径一律使用绝对路径；搜索范围是用户主目录，不包括资源库和隐藏文件；「下载」指 `~/Downloads`；
- **工具列表**；
- **评测**（第 11.3 节）：其中一部分会作为 `@` 列表中的示例。

### 7.2 工具的组成

- **名称与说明**：写清何时使用、何时不该使用、参数格式，并附一个例子；
- **输入**：一个对象，每个参数都有说明；日期一律用带时区的 ISO 8601；
- **是否只读**；
- **确认函数**（可选）：在执行之前用同一份输入调用。返回空表示不需要确认；否则返回卡片内容，包括说明、若干「名称 / 值」明细，以及是否使用破坏性样式；
- **执行**：返回简洁的文字结果；出错时，返回能指导下一步的错误信息。

### 7.3 `@文件` 的工具

| 工具 | 作用 | 只读 | 确认 |
|---|---|---|---|
| `search_files` | 按名称、类型、修改 / 添加 / 打开时间、所在目录、内容关键词，搜索文件和文件夹 | 是 | 不需要 |
| `list_folder` | 列出文件夹里的内容，可以按类型过滤 | 是 | 不需要 |
| `open_file` | 用默认 App 打开 | 否 | 不需要；遇到可执行内容直接拒绝 |
| `reveal_in_finder` | 在访达中显示 | 否 | 不需要 |
| `create_folder` | 新建文件夹 | 否 | 不需要 |
| `move_files` | 移动或改名，一次可以处理多个文件 | 否 | 需要：逐项列出「原路径 → 新路径」 |

各工具的约束：

- **路径范围**：所有工具只处理主目录下、文件搜索范围内的路径，与现有的文件搜索一致——不包括资源库和隐藏目录。
- **`search_files`**：
  - 每条结果包含名称、路径（用 `~` 缩写）、类型、修改时间和大小，最多返回 20 条；结果更多时，注明总数以及可以用来缩小范围的参数；
  - 设置中关闭了文件搜索时，返回错误；
  - 现有的文件搜索只按名称匹配，需要扩展出类型、时间、目录、内容这些条件；内容关键词依赖本机的 Spotlight 索引。
- **`open_file`**：拒绝打开的类型包括 App 包、脚本、安装包、磁盘映像、自动化流程、终端配置、网址快捷方式等，按文件类型判断。
- **`move_files`**：
  - 目标位置已有同名文件时，这一项报错，不覆盖；
  - 目标文件夹不存在时报错，并提示先用 `create_folder` 新建。

## 8. Agent 循环

### 8.1 流程

1. **组装消息**：系统提示、当前时间、这段对话的历史、新的输入。如果这段对话 `@` 过某个扩展，就附带它的领域说明和工具定义。
2. **请求模型**，流式接收。
3. 如果模型只回了文字，本轮结束。
4. 如果模型要调用工具，就逐个处理：
   1. 解析参数；
   2. 调用确认函数；
   3. 需要确认、且这个工具没有被设为总是允许时，弹出卡片等你决定；
   4. 执行，或记为「已拒绝」；
   5. 把结果加回对话，回到第 2 步。

### 8.2 上限

- 每条消息最多 10 次模型请求；
- 每条消息最多 5 次打开类操作（`open_file`、`reveal_in_finder`）；
- 同一工具以同样的参数连续调用 3 次时，停止；
- 两次收到数据之间的超时沿用现在的 3 分钟。

### 8.3 出错

- **工具执行失败**：错误作为工具结果交给模型，不中断循环。
- **参数不对**：返回说明和正确格式，让模型重试。
- **接口出错**：本轮失败，显示原因，按 `↵` 重试。
- **模型不支持工具调用**：只有在使用 `@文件` 时才会遇到。此时显示「当前模型不支持工具调用，无法使用 @文件」；这段对话中的普通问答不受影响。

### 8.4 系统提示要点

- 沿用 Quick AI 现有的系统提示。
- 使用 `@文件` 时追加以下要求：
  - 先搜索、确认目标，再动手；
  - 批量改动之前，先用一句话说明打算怎么做；
  - 找不到时如实说明，并给出相近的结果；
  - 信息不足时直接提问。

## 9. 安全与隐私

### 9.1 安全

- 工具只能处理主目录下、文件搜索范围内的路径。
- 会改动文件位置或名称的操作（`move_files`）一律先确认。打开、在访达中显示、新建文件夹不需要确认，但打开会拒绝可执行内容，并且计入打开次数上限。
- 不覆盖、不删除：本版的所有改动都可以手动恢复。
- 本版几乎接触不到不可信内容，也没有能把数据发出去的工具：
  - 不读取文件内容。内容关键词由本机 Spotlight 匹配，模型只能看到匹配到的文件名；
  - 不联网，也不打开网址。
- 卡片明细由工具按实际参数生成，展示的是原始路径，而不是模型写的描述。Raycast 也提醒过：卡片描述由 AI 生成，允许前要核对。

### 9.2 隐私

- 只有使用了 `@文件` 的对话，才会把文件名、路径、修改时间等信息发送给接口；`@` 列表中的说明会写明这一点。
- 功能清单和使用指南中的隐私说明同步更新。

## 10. 设置

- Quick AI 设置中新增「AI 扩展」分组：
  - 列出所有扩展（本版只有「文件」），每个扩展都可以单独关闭；关闭后，它不再出现在 `@` 列表中；
  - 「已总是允许的工具」：列出全部，可以逐个移除，也可以全部清空。
- 接口地址、模型、API Key、思考强度沿用 Quick AI 现有的设置。
- 不新增总开关。

## 11. 测试与验收

### 11.1 单元测试

- **客户端**：
  - 请求中带上了工具定义；
  - 分片到达和一次给全的工具调用，都能拼接完整；
  - 工具结果按正确格式回填。
- **循环**：
  - 用脚本化的模型桩，先返回工具调用，再返回回答；
  - 各项上限生效；
  - 工具错误能回填给模型；
  - 重复调用时停止；
  - 你拒绝后，「已拒绝」的结果会回填给模型。
- **确认**：
  - 确认函数返回空时直接执行；返回内容时等待你决定；
  - 允许、总是允许、拒绝三条路径都正确；
  - 「总是允许」会被记住，也可以清空。
- **工具**：
  - 参数校验；
  - 路径范围检查；
  - 不覆盖已有文件；
  - 拒绝可执行内容。
- **对话与面板**：
  - 追问时带上历史；
  - ⌘N 开新对话；10 分钟后自动开新对话；
  - 失焦收起时任务不中断；
  - 在确认卡片上按 `Esc` 是拒绝。

### 11.2 手工验收

在 Xcode 中运行，使用一个支持工具调用的模型：

1. 不用 `@`，问「1+1 等于几」：与现在一样，直接回答。
2. 接着追问「再乘以 3」：能接上上一轮。
3. 「@文件 找出上周下载的 pdf」：按时间、类型、目录搜索，并列出结果。
4. 「@文件 把下载文件夹里的截图移到 图片/截图」：先搜索，再弹出确认卡片逐项列出；按 `↵` 后完成。
5. 同上，这次按 `Esc`：不执行，模型说明操作已取消。
6. 「@文件 把这几个文件按『发票-月份』的格式改名」：卡片列出改名前后的名称；按 `⌘↵` 后，再做类似操作就不再询问；在设置中清空后，又会重新询问。
7. 「@文件 打开 install.command」：拒绝，并说明原因。
8. 「@文件 打开最近下载的发票」：搜索后打开文件；面板收起后，任务仍然完成。
9. 运行中按 `Esc`：任务中断，面板关闭。
10. 移动到已有同名文件的位置：这一项报错，不覆盖。
11. 换一个不支持工具调用的模型，用 `@文件` 提问：提示不支持；不用 `@` 时问答正常。
12. 在设置中关闭「文件」扩展：`@` 列表中不再出现它。

### 11.3 评测

参照 Raycast 的结构，每条评测包含三部分：

- **输入**：一句带 `@文件` 的话；
- **模拟返回**：这条评测中各工具返回什么。评测时不会真的搜索或移动文件；
- **期望**：
  - 调用了哪个工具，参数是否符合，例如类型是 pdf、添加时间从上周一开始；
  - 回答里包含什么；
  - 没有调用某个不该调用的工具，例如只是问问时，不应调用 `move_files`。

起步 20 条，用真实模型运行。接口配置从环境变量读取，未设置时跳过。一部分评测会作为 `@` 列表中的示例。

## 12. 实施顺序

每一步一个提交，都可以在 Xcode 中单独验证。

1. **客户端支持工具调用**，不改界面。验收：单元测试通过。
2. **扩展与工具模型、确认机制、循环，以及 `@文件` 的 6 个工具**。验收：桩测试通过，评测框架可以运行。
3. **Quick AI 的追问与新对话**（暂不含 `@`）。验收：手工验收第 1–2 条。
4. **`@` 选择扩展、步骤行、确认卡片，以及设置中的「AI 扩展」分组**。验收：手工验收第 3–7 条、第 10–12 条。
5. **面板失焦时不中断任务，再次呼出时恢复**。验收：手工验收第 8–9 条。
6. **文档**：更新功能清单、使用指南和隐私说明。

## 13. 风险

| 风险 | 处理 |
|---|---|
| 各家模型的工具调用质量参差不齐 | 至少实测两家服务；用评测集比较 |
| 各家流式工具调用的格式不同 | 同时兼容分片到达和一次给全两种情况，用单元测试覆盖 |
| 思考模式与工具调用组合时，部分服务要求回传思考内容 | 实测；需要时在客户端中适配 |
| 批量改名或移动出错 | 卡片逐项列出改动；不覆盖已有文件；所有改动都能手动恢复 |
| 面板高度放不下步骤和卡片 | 步骤行只占一行；卡片明细超出时可以滚动 |
| 追问改变了「修改输入就丢弃回答」的旧习惯 | 在使用指南中说明；⌘N 开新对话 |

## 14. 之后的顺序

按 Raycast 的路径逐步扩展，详细设计见 [`agent-plan.md`](agent-plan.md)：

1. 用 `@` 附带上下文：选中文字、当前窗口、截图；
2. 更多扩展：`@应用`、`@剪贴板`、`@提醒事项`、`@日历`；
3. 移到废纸篓，以及 Auto 档（按风险自动判断是否需要确认）；
4. 自动发现扩展；
5. AI Chat 窗口、历史记录、Agents 预设；
6. MCP、Skills、定时任务。
